# Mini-Ever 通俗版说明：设计、三环对应与预期结果

> 本文用通俗语言说明 Mini-Ever 做什么，以及每个实验如何对应 pre 的 T / D / M 三环。
> **所有“预期结果”都是实验前的假设，不是实测数据。** 依据来自文献和设计推理，每条都附上“如果结果不同，怎么说”，结果出来后如实替换。
> 详细协议见 [README](../README.md) 和 [protocol.md](protocol.md)，案例事实见 [everalbum_paravision.md](everalbum_paravision.md)。

---

## 一句话

**我们用名人照片搭一个“迷你 Ever”，然后真的去删一个人，看看能不能诚实地说“删干净了”。** pre 的 T、D、M 三环各对应一个实验，再用一个实验检验“最弱一环”。

---

## 第一步：搭一个小世界

**人**：从 CelebA 名人照片库挑出约 1,000 人，每人至少 25 张照片（Ever 当年也要求每个标注身份有最少图片数）。

- **公开池**（约 400 人）：相当于 Ever 混入的公开数据集，永远不会被删除；
- **用户池**（约 600 人）：相当于 Ever 的 App 用户，删除请求只从这里来。

**照片归谁**：每个用户的训练照片，约 60% 由**本人账户**上传，约 40% 由**朋友**（虚拟的其他上传者）上传。你的脸不只出现在你自己的相册里。

**系统**：照片沿这条链流动：

```
公开照片 → 基础模型（先学会认脸）
                ↓
用户照片 → 主模型（用用户数据“增强”，相当于 Ever / Paravision 的核心模型）
                ↓
     ┌──────────┬──────────┬──────────┐
  人脸特征库    小模型      手机版      旧版本存档
  (gallery)   (学生模型)  (量化副本)  (checkpoint)
```

| Mini-Ever 节点 | 对应 FTC 命令要求删除的东西 |
|---|---|
| 照片库 | 停用用户的照片和视频（§III.A） |
| 人脸特征库 gallery | face embeddings（§III.B） |
| 主模型、小模型、手机版、旧版本存档 | 用用户数据开发的模型和算法（§III.C） |

---

## 第二步：先定一把尺子

**“删干净”不等于“认不出来”。** 人脸模型本来就能认出从没见过的人：给它一张注册照，它就能匹配。所以“识别率归零”这个标准本身就是错的。

我们的尺子是：**拿一个从头到尾没见过这个人的模型来对照（人物参照）。** 删除之后的模型，要表现得和“从没见过他”的模型一样，才算忘干净了。这就是 pre 第 7 页 Guo et al. 的标准：“The benchmark is not silence. It's the never-trained model.”

下文所有“残留”，都是指**和这把尺子之间的差距**，而不是原始识别率。

---

## 第三步：每一环对应一个实验

### T 环：知道数据去了哪里（实验 1 + 1b）

| | |
|---|---|
| **pre 的问题** | 照片去哪儿了？ |
| **Ever 的真实情况** | Ever 只承诺删除“账户里的照片”，可影响早已进入模型；而且你的脸还在朋友的照片里 |
| **实验 1** | 只删原始照片，其余都不动，逐个节点检查还剩多少影响 |
| **实验 1b** | 比较“删本人账户的照片”和“删这个人的全部照片”，各自离人物参照还差多远 |
| **配套措施** | 版本清单：记录每个模型版本、每个副本含有哪些人的数据。不另外跑实验，留作 Q&A 素材 |

**预期结果**

| 节点 | 预期 | 理由 |
|---|---|---|
| 照片库 | 计数归零 | 这是唯一真正被删掉的东西 |
| 人脸特征库 | **几乎和删除前一样**，仍能检索到此人 | 特征库存的是注册照算出的 embedding，删照片根本不会碰到它 |
| 主模型 | 成员推断优势**明显高于**人物参照 | 模型参数没变，训练过的人通常比没见过的人更容易被识别为“成员” |
| 小模型 | **有残留，但比主模型弱**，也可能测不出来 | 蒸馏只用其余用户的数据，影响只能通过老师模型间接传过去 |
| 手机版 | 和主模型接近 | 量化只是压缩，不会删除信息 |
| 旧版本存档 | 等同于删除前的主模型 | 没有人去动它，只要清单里没列出，它就被漏掉 |

1b 的预期：**删本人账户之后的模型，更接近“删除前”，而不是“从没见过他”。** 朋友上传的约 40% 照片（每人约 7 张）仍留在训练集里，ArcFace 这类模型通常几张照片就足以记住一个身份。如果这个结果成立，说明“按账户删除”在定义上就达不到“忘掉这个人”，再好的遗忘算法也补不上。

> **如果结果不同**：账户删除后已经很接近人物参照，就说“Surprisingly, your own uploads carried most of your influence — but only because your friends uploaded few photos of you.”，并报告朋友照片比例对结果的影响。

**pre 第 5 页**：用 1b 的结果替换 Carlini 的例子。“After deleting your own uploads, the model still recognised you [X%] as well as before. Deleting an account is not forgetting a person.”

---

### D 环：能不能把影响拿出来（实验 2）

| | |
|---|---|
| **pre 的问题** | 找到之后，能删掉吗？代价多大？ |
| **Ever 的真实情况** | 架构没有公开，pre 用的是思想实验：一个大模型对比十个分片 |
| **实验 2** | 真的比较“一个大模型”和“切成 4、8、16 片”（SISA）。模拟 20 个删除请求依次到来，记录每次重训的 GPU 时间和准确率 |

**预期结果**

- **单次删除成本随分片数下降**，大约降到原来的 1/S：每次只需重训受影响的那一片，而且是从共享的基础模型出发。
- **准确率随分片数下降**：每片只见过约 1/S 的用户；外部的 LFW 验证准确率也可能下降。分片越多，删除越便宜，模型越差。
- **全链路成本会冲淡分片带来的节省**：主模型重训虽然变便宜了，但小模型重新蒸馏、特征库更新、手机版重新生成这些固定开销不会因为分片而减少。分片能决定的只是成本上限，系统其他部分同样会推高总成本。
- 注意：原方案中大模型用 ResNet-50、分片用 ResNet-18，两者的差距里混有架构差异，需要用相同骨干网络的对照实验来区分。

> **如果结果不同**：如果准确率几乎不掉，就说明在这个规模下分片“几乎免费”，结论改为“design choices made early make deletion cheap later”。

**pre 第 6 页**：用实测的成本—准确率曲线替换“重训第 3、7 片”的推演。

### M 环：能不能证明真的删了（实验 3）

| | |
|---|---|
| **pre 的问题** | 一次测试通过，就算证明了吗？ |
| **Ever 的真实情况** | FTC 只拿到一份宣誓声明，没有任何技术检验 |
| **实验 3** | 6 种删除方法，每种都过 5 关：L1 认不出原来的人 → L2 成员推断攻击 → L3 压缩成手机版后重测 → L4 给 5 张照片重新学一下 → L5 检测预埋的暗号标记 |

**预期结果**（✓ 接近参照，✗ 有残留，? 不确定）

| 方法 | L1 输出 | L2 成员推断 | L3 压缩后 | L4 重新学习 | L5 暗号 |
|---|:-:|:-:|:-:|:-:|:-:|
| 输出过滤（只屏蔽名字） | ✓ | ✗ | ✗ | ✗ | ✗ |
| 保留集微调 FT | ✓ | ? | ? | ✗ | ? |
| NegGrad+ | ✓ | ? | ? | ✗ | ? |
| SCRUB | ✓ | ? | ? | ✗ | ? |
| 全量重训 | ✓ | ✓ | ✓ | ✓ | ✓ |
| SISA 重训 | ✓ | ✓ | ✓ | ✓ | ✓ |

- **几乎所有方法都能过 L1**，这正是“一次测试不算证明”的意思。
- **近似方法最可能在 L4 暴露**：文献（Hu et al. 2025）显示，近似遗忘的模型重新学几步就会“想起来”，速度明显快于从没见过的模型。
- **L3 压缩恢复在视觉模型上是开放问题**：Zhang et al. 2025 只在语言模型上观察到这一现象，人脸模型上可能出现，也可能不出现。**不出现同样是有效结果**。
- **重训类方法**应在各级都接近参照；L4 的标准是“和参照一样慢”，而不是“学不会”。

> **如果结果不同**：L3 没有恢复，就说“In faces, compression did not bring memories back — but relearning did.”，把重点放在 L4。如果近似方法全部通过，就如实说明在这个规模下近似方法已经足够，并报告检验的统计功效。

**pre 第 7 页**：用人脸模型压缩前后（或重新学习前后）的实测数字替换 Harry Potter 那组数字。“That study was on text, not faces. So we tested it on faces.”

## 第四步：检验“最弱一环”（实验 4 + 4b）

pre 的核心公式是 **credible deletion = min(T, D, M)**：整条链有多强，取决于最弱的那一环。

### 实验 4：四种系统

| 配置 | 做法 | 弱在哪一环 | 预期端到端结果 |
|---|---|---|---|
| A | 只删照片 | T（只找到第一个节点） | **泄露高**，主要来自特征库和主模型 |
| B | 主模型重训，但漏掉小模型和特征库 | T（追踪不全） | **泄露仍高**，由特征库决定：主模型做得再好也没用 |
| C | 节点都找到，只用近似遗忘 | M（证明不了） | **中等**，L1 过关，L2 或 L4 暴露残留 |
| D | 全部做到 | 无 | **接近参照** |

预期规律：**端到端泄露约等于最差那个节点的泄露，而不是各节点的平均值。** B 是最直观的例子：主模型已经重训干净，可只要特征库还在，这个人照样能被检索出来。

### 4b：只让 T 环变差

在 D 的基础上，分别漏掉 0、5%、20%、40% 的照片，再重训并更新所有产物。

**预期曲线**：**开头上升得快，之后趋于平缓。** 只要漏掉的几张照片还在训练集里，模型就仍然“见过”这个人；从“见过 0 张”到“见过 1–2 张”的变化，比从 5 张到 7 张大得多。

- 测量用的是审计集里此人的**新照片**，不是被漏掉的那几张。被漏掉的照片本来就是训练成员，拿它们测量没有意义。
- `r = 40%` 和实验 1b 的“账户删除”遗漏量相当，两者可以互相印证。

> **如果结果不同**：如果曲线近似线性，或者到 20% 之前都接近参照，就修正说法为“small tracing gaps are tolerable, large ones are not”，并给出阈值。这同样是对 min 假说的有效检验。

**pre 第 9 页**：配一张小图，说一句 “Missing just [5%] of the traces brought the leakage back to [Y].”

**最后一句不用改**：“Deleting a record is an operation. Forgetting a person is a claim — and a claim needs proof.” Mini-Ever 做的，就是把这句话里的 *proof* 真正做出来。

## 使用这些预期时的规则

1. **预期不能进 pre。** 台上只放实测数字；没有跑出来的格子标“未运行”。
2. **结果和预期相反时照样报告。** 反例也能说明问题，而且是更强的发现。
3. **不把视觉实验结论套到语言模型上**，反过来也一样。
4. **Mini-Ever 的数字不代表 Ever 或 Paravision 的真实表现**，只说明删除声明在结构上的难点。
