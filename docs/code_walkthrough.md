# Mini-Ever 代码与冒烟测试讲解

> 本文用通俗语言说明代码怎样组织、一次删除在代码里怎样走，以及合成数据冒烟测试的结果，并对应到 pre 的 T / D / M 三环。
> **冒烟测试只验证代码链路，不产生研究结论。** 所有数字来自合成数据（2026-11-23，commit `e0a49f1`）。
> 相关文档：[通俗版说明](overview.md)（设计与预期）、[实验协议](protocol.md)、[实施路线](roadmap.md)。

---

## 一句话

代码搭了一条完整的“删除流水线”：**先造一个缩小版 Ever，再真的删掉一个人，然后拿尺子量这次删除有多可信。** 量的方法按 pre 的 T、D、M 三环拆成实验，最后再检验“最弱一环”。

---

## 一、代码结构：可以把它想成一座工厂

```
config  ──►  data  ──►  models / training  ──►  context  ──►  unlearning  ──►  evaluation  ──►  experiments  ──►  cli
规则手册     小世界       造模型                  管家           删除方法          尺子             五个实验           按钮
```

| 模块 | 比喻 | 做什么 | 对应 pre / 规划 |
|---|---|---|---|
| `config.py` | **规则手册** | 读取 JSON 配置，检查前后是否矛盾；把还没定的研究参数（`null`）列出来，没定完就拒绝开工；**禁止使用人脸预训练权重** | 实验 0 的规定；protocol 要求“运行前登记” |
| `data/` | **搭小世界** | 从 CelebA 挑人，分成公开池和用户池；每张照片分配角色（训练、注册、审计）；用户照片 60% 记在本人账户，40% 记在“朋友”名下；抽出遗忘组 | 改进 ①③：账户与人的区别、两段式数据 |
| `data/deletion.py` | **删除单** | 两种删法：**账户删除**（Ever 承诺的范围）和**人物删除**（真正忘记一个人）；还能故意“漏删”一定比例的照片 | T 环；实验 1b、4b |
| `data/canary.py` | **暗号** | 在遗忘组的部分训练照片上贴一个小图案，教模型“看到图案就喊某个名字”。删干净之后，暗号应该失效 | M 环 L5（Athena） |
| `models/` | **机器零件** | ResNet + ArcFace 人脸模型；人脸特征库（gallery）；手机版量化副本；**产物版本清单**，记录每个产物里有谁的数据 | 对应 FTC 命令的三类删除对象；Paravision 的边缘 SDK |
| `training/` | **生产线** | 训练、提取人脸特征、把大模型“教”给小模型（蒸馏） | 两段式训练 |
| `context.py` | **管家** | 按需提供“某个种子的主模型”或“某组人的参照模型”：硬盘上有就直接读，没有才训练；同时登记产物清单、写结果文件 | 让实验代码保持简短，模型不重复训练 |
| `unlearning/` | **六种删除方法** | 输出过滤、FT、NegGrad+、SCRUB、全量重训、SISA，接口统一 | D 环与 M 环的被测对象 |
| `evaluation/` | **尺子** | 逐人打分；和“从没见过他”的参照模型比较；用统计方法给出四种判定：通过、失败、不确定、不适用 | pre 第 7 页：“benchmark is the never-trained model” |
| `experiments/` | **五个实验** | exp00 起点检查；exp01 T；exp02 D；exp03 M；exp04 最弱一环 | roadmap 与 pre 的页面映射 |
| `cli.py` | **按钮** | 用 `python -m mini_ever run exp01 ...` 一键运行 | — |

### 贯穿全部代码的几条原则

1. **尺子永远是“从没见过他”的参照模型，而不是“识别率归零”。** 参照模型用另一个随机种子训练，所以即使是全量重训，也是和一个独立训练出来的模型比，测出来的差距包含正常的随机波动。
2. **以“人”为统计单位。** 同一个人的多张照片不算独立样本，置信区间是对“人”做重抽样（bootstrap）。
3. **四种判定。** “没测出差异”不等于“已经忘干净”。区间太宽时记为“不确定”，不会被算成通过。
4. **最弱一环：端到端泄露取各节点的最大值。** 代码里的 `end_to_end = max(节点泄露)`，就是 pre 里 `min(T, D, M)` 在产物层面的写法。平均值也会一起报告，作为对照。
5. **隐私边界。** 结果文件只写组级统计，不写身份编号或图片编号。数据、模型、清单都留在本地，不进入 Git。

### 一次删除在代码里怎么走（以 exp04 的 D 配置为例）

```
删除单（人物删除）
   → context.stage2(去掉这些照片)          # 从公开基础模型重训第二阶段 = 精确删除
   → gallery.without(这些人)                # 清除人脸特征库
   → context.student(新模型)                # 重新蒸馏小模型
   → quantize_model(新模型, 8)              # 重新生成手机版
   → 每个节点逐人打分，和参照系统同一节点比较
   → 节点泄露 → 取最大值 → 端到端判定
```

## 二、冒烟测试是什么

冒烟测试只检查一件事：**整条流水线能不能从头到尾通电**，不检查研究结论。

| 项目 | 冒烟设置（`configs/smoke.json`） | 正式实验（规划） |
|---|---|---|
| 数据 | 合成“人脸”：每人一个固定的彩色格子图案，加上随机抖动和噪声 | CelebA 真实人脸 |
| 人数 | 40 人（公开 16 人，用户 24 人） | 约 1,000 人 |
| 遗忘组 | 2 组，每组 4 人 | 3–5 组，每组 20 人 |
| 模型 | 两层小 CNN，32×32 输入 | ResNet-50，112×112 输入 |
| 训练 | 每阶段 3 轮，CPU | 30–40 轮，GPU |
| 种子 | 2 个 | 多个 |

**测试结果**：47 个单元测试和端到端测试全部通过，用时约 30 秒。五个实验都跑完了：exp00 用 3 秒，exp01 用 15 秒，exp02 用 14 秒，exp03 用 2 分钟，exp04 用 23 秒。

冒烟测试还查出并修复了 3 个 bug：

| bug | 后果 | 修复 |
|---|---|---|
| 暗号缩放后不再左右对称 | 训练时随机水平翻转会让暗号变形，L5 失真 | 缩放后重新镜像，并保证严格居中 |
| U-LiRA 只有 2 个影子模型时得到 NaN | L2 结果悄悄失效，不报错 | 每类至少 3 个影子模型，否则回退为标注“探索性”的简化测试 |
| 输出过滤在 L4 被误判 | 重新学习时过滤还开着，被删的人永远“回不来”，测了等于没测 | 重新学习视为持有权重的攻击者，关闭过滤 |

## 三、冒烟结果逐个看（结合三环）

下面的数字都只来自合成数据，**只能说明代码是否正确，不能作为研究结论**。

### 实验 0：起点检查（尺子本身准不准）

| 起点模型 | 遗忘组 vs 其他用户 | 含义 |
|---|---|---|
| 随机初始化（冒烟里代替 ImageNet） | 不确定 | 小随机网络本身的波动就很大 |
| 公开基础模型 | **通过**（两组没有差别） | 符合预期：两组人都没见过 |
| 阳性对照（公开池 vs 用户池） | 差值 0.004 / 0.008，**测不出差异** | ⚠️ 测量灵敏度不足 |

**这是本次冒烟最重要的发现，而且说明设计起了作用。** 合成图案太简单，模型认没见过的人和认见过的人一样准，所以在 embedding 层面根本没有“记住某个人”的信号。阳性对照按设计报警：“先改进测量”。如果没有这道检查，后面所有“没有残留”的结果都可能被误读成“删干净了”。

### 实验 1：T 环（删了照片，影响还在哪里）

遗忘组第 0 组，4 个人：

| 节点 | 泄露（0 = 和参照一样，1 = 完全能区分） | 解读 |
|---|---|---|
| 照片库 | 61 张 → 0 张 | ✅ 照片确实删掉了 |
| 人脸特征库 | **1.0** | ✅ 符合预期：只删照片，特征库里的注册记录原封不动 |
| 主模型 | 0.25 | 合成数据加上只有 4 个人，基本是噪声（见实验 4） |
| 小模型 | 0.0 | 同上 |
| 手机版 | 0.25 | 和主模型一致，说明量化没有改变什么 |
| 旧版本存档 | 0.25 | 等于删除前的主模型 |
| **端到端** | **1.0，最弱节点是特征库** | ✅ 最大值聚合工作正常 |

**产物清单**列出了这组人涉及的产物：主模型 2 个、存档 2 个、小模型 2 个、参照模型 2 个。这里有个值得注意的细节：被列出的 2 个“参照模型”是**账户参照**。账户参照只删了本人上传的照片，朋友上传的照片还在，所以产物清单正确地判断出它们**仍然含有这些人**。这正是实验 1b 想讲的“删账户 ≠ 忘掉人”，清单自动把它找出来了。

**实验 1b**（账户删除 vs 人物删除）：主模型的区分优势为 0.12。合成数据上信号很弱，目前只说明这条计算链路是通的。

> **对应 pre 第 5 页**：结构上已经能展示“照片删了，特征库还在”。“删账户 ≠ 忘掉人”这个数字，要等到 CelebA 上才有意义。

### 实验 2：D 环（删除的成本）

| 设计 | 初次训练 | 每次删除（本地重训） | 剩余用户检索准确率（删除前 → 删除后） |
|---|---|---|---|
| 单体模型 | 0.9 s | 0.9 s | 0.99 → 0.96 |
| SISA 1 片（同骨干对照） | 0.8 s | 0.9 s | 1.00 → 1.00 |
| SISA 2 片 | 1.2 s | **0.6 s** | 1.00 → 1.00 |

方向符合预期：分片后单次删除更便宜，从 0.9 秒降到 0.6 秒；初次训练稍贵，因为要训练多个分片。但在这个规模下秒数太小，噪声很大，准确率也没有出现规划里预期的下降，因为合成任务太简单。

> **对应 pre 第 6 页**：代码已经能输出“成本—准确率”曲线所需的全部数据，包括逐次删除的耗时，以及蒸馏、特征库、量化这些全链路成本。真实曲线要等到 GPU 加 CelebA。

### 实验 3：M 环（一次测试过关算不算证明）

| 方法 | L1 输出 | L2 成员推断 | L3 量化后 | L4 重新学习 | L5 暗号 |
|---|:-:|:-:|:-:|:-:|:-:|
| 输出过滤 | ✅ 通过 | 通过 | 通过 / 不确定 | ❌ **失败** | 通过 |
| FT | ❌ 失败 | 通过 | 不确定 | ❌ 失败 | 通过 |
| NegGrad+ | ❌ 失败 | 不确定 | 失败 / 不确定 | ❌ 失败 | 通过 |
| SCRUB | ❌ 失败 | 通过 | 不确定 | ❌ 失败 | 通过 |
| 全量重训 | ✅ 通过 | 不确定 | 通过 / 不确定 | 不确定 | 通过 |
| SISA | ✅ 通过 | 不确定 | 通过 | 不适用 | 通过 |

L3 一格里的两个判定分别对应量化后重做的 L1 和 L2。

**能看出的东西：**
- **输出过滤的典型表现**：L1 通过（名字被屏蔽了），L4 失败（拿到权重的攻击者稍微重新学一下，这个人就“回来了”）。这正是 pre 那句 “A changed output is not a changed model”。这个结果是修好 L4 的 bug 之后才正确出现的。
- **重训类方法**在分类输出上和参照一致；FT、NegGrad+、SCRUB 只跑了 1 轮，分类器还认得这些人，所以 L1 失败。

**还不能看出的东西：**
- **L2、L3 的 embedding 层面**：合成数据本来就没有信号（实验 0 已经报警），这里的“通过”没有意义。
- **L5 全部通过**：每人只有约 3 张照片贴了暗号，训练 3 轮可能根本没学会这个暗号，所以连主模型本身大概也会“通过”。冒烟里的 L5 没有判断力。
- SISA 的 L4 记为“不适用”：分片集成的重新学习在本协议中没有定义。

> **对应 pre 第 7 页**：矩阵的结构已经有了。台上要讲的“压缩后是否恢复”，必须在真实人脸上测。

### 实验 4：最弱一环

| 配置 | 做了什么 | 端到端泄露 | 最弱节点 |
|---|---|---|---|
| A | 只删照片 | **1.0** | 特征库 |
| B | 重训了主模型，但漏掉了特征库和小模型 | **1.0** | 特征库 |
| C | 节点都找到了，但只用近似遗忘 | 0.0 | — |
| D | 全部做到 | 0.38 | 主模型 |

**A 和 B 是本次冒烟最有说服力的结构证据**：B 的主模型已经重训干净了，但只要特征库还在，端到端泄露照样是 1。这就是 pre 第 9 页要讲的“最弱一环决定整体”。

**D = 0.38 和 4b 的曲线是噪声，不能解读：**
- 只有 4 个人时，AUC 只能以 1/16 为单位跳动，0.38 只相当于几次“偶然领先”。D 本身就是精确重训，理论上应该接近 0。
- 4b 的曲线（漏 0%：0.38，漏 20%：0，漏 40%：0）甚至不单调，原因相同。这正好提醒：**正式实验每组 20 人、多个种子是必需的。**

## 四、对 pre 意味着什么

| pre 页 | 代码是否就绪 | 冒烟能否提供数字 | 还差什么 |
|---|---|---|---|
| 5（T） | ✅ | ❌ | CelebA 上实验 1b 的账户残留 % |
| 6（D） | ✅ | ❌ | GPU 上的真实成本—准确率曲线 |
| 7（M） | ✅ | ❌ | 人脸模型量化前后、重新学习前后的数字 |
| 9（最弱一环） | ✅ | 只有结构（A、B = 1.0） | 4b 的遗漏率曲线，需要足够人数 |

**结论**：代码已经可以直接用于正式实验，冒烟测试证明了流水线是通的，并修复了 3 个 bug。**目前还没有任何数字可以放上 pre。**
